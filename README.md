# AIR STRUM · 空气吉他

只用摄像头和双手，在浏览器里演奏吉他和弦。左手摆手势选和弦，右手上下挥动扫弦；没有键盘演奏或触屏演奏模式。

## 本地运行

需要 Node.js 22 或更新版本，以及带摄像头的现代浏览器。桌面 Chrome / Edge 是这一版的优先验证环境。

```sh
npm ci
npm run setup
npm run dev
```

打开终端显示的 `http://localhost:5173`，点击“开启摄像头”并允许访问。第一次点击同时启用浏览器音频。建议佩戴耳机、保持光线均匀，让双手完整入镜。

`npm run setup` 从固定地址下载 MediaPipe Hand Landmarker float16 v1 模型（约 7.8 MB），并把已锁定版本的 WASM 和识别库复制到 `public/`。这一步需要联网；运行时所有脚本、模型和 WASM 都由本地站点提供，摄像头画面不会上传。模型和生成文件没有提交到 Git，可重复运行 setup 恢复。

## 怎么弹

像抱着吉他一样，**两只手的手心都朝向自己，手背朝向镜头**；也兼容手心朝镜头的姿势。左手保持手势约 110 ms。支持 12 种演奏手势，加握拳消音，共 13 种状态。下表数字是手势编号，并不是伸出的手指数；三指手势是**食指、中指、无名指**。

| 编号 | 手势 | 默认和弦（均可自定义） |
| --- | --- | --- |
| 1 | 只伸食指 | C |
| 2 | 食指、中指 | G |
| 3 | 食指、中指、无名指 | Am |
| 4 | 四指伸直，拇指收起 | F |
| 5 | 五指张开 | Dm |
| 6 | 只伸拇指 | Em |
| 7 | 只伸小指 | D |
| 8 | 食指 + 小指 | A |
| 9 | 拇指 + 食指（L） | E |
| 10 | 拇指 + 食指 + 中指 | Bm |
| 11 | 拇指 + 小指（六） | C7 |
| 12 | 拇指 + 食指 + 小指 | G7 |
| 0 | 握拳 | 固定消音，不映射和弦 |

右手可以自然松握，手心朝自己，不需要张开给镜头看。让手部中心从参考横线上方扫到下方，或从下方扫到上方。横线在视频高度的 55% 处；需要跨过横线，并达到速度门槛，才触发一次扫弦。下扫依次拨低音到高音，上扫反过来，动作越快力度越大。先在横线一侧停好，再做幅度明显的动作。灵敏度越高，触发所需速度越低。

画面是镜像预览。若模型把两手功能判反，点击“交换双手”，以骨架旁的“和弦手 / 扫弦手”标签为准。左手移出画面约 450 ms 后，和弦释放并消音；切到后台会关闭摄像头，回到页面后需要重新开启。

## 和弦库与歌曲预设

五根手指只区分伸直 / 收起时有 2⁵ = 32 种理论组合，很多组合很难自然摆出，也可能互相遮挡；本程序选择 12 种相对常见的手形，另保留握拳消音。它不识别其余 19 种组合，也没有承诺真人手势在所有角度都能稳定识别。复杂手势可以在自己的歌曲映射里不用；同一和弦也能分配给多个手势。

和弦没有统一的固定总数，取决于是否区分扩展音、转位、斜杠低音和同音异名。本版按 **12 个根音 × 16 种类型 = 192 个和弦名称**提供配置，C# 与 D♭ 等同音异名合并为同一根音，不把转位单独计数。这是可选和弦库数量；一套歌曲同时直接映射 12 个和弦，不要求记 192 种手势。

| 类型 | 示例 |
| --- | --- |
| 大三 / 小三 | C / Cm |
| 属七 / 大七 / 小七 | C7 / Cmaj7 / Cm7 |
| 挂二 / 挂四 | Csus2 / Csus4 |
| 加九 | Cadd9 |
| 大六 / 小六 | C6 / Cm6 |
| 减三 / 减七 / 增三 | Cdim / Cdim7 / Caug |
| 半减七 | Cm7♭5 |
| 属九 / 小九 | C9 / Cm9 |

在“歌曲预设”中：

1. 选择预设即可切换整套映射。内置“常用和弦”“流行 · C–G–Am–F”“七和弦 · ii–V–I”。
2. “编辑映射”修改当前预设，“另存为新曲”复制当前映射并命名。每个手势可分别选择根音与类型；修改后点击“保存映射”。取消不会写入修改。进入编辑会先停止摄像头演奏。
3. 配置自动保存在当前浏览器、当前站点的 localStorage 中，刷新仍保留。不同浏览器、域名、端口或设备不共享存储；清除站点数据会删除预设。
4. “导出备份”下载全部预设的 JSON。“导入预设”验证文件后追加，不覆盖已有歌曲；重复导入会生成副本。最多保存 100 套预设，导入文件不超过 1 MB。存储不可用时仍可在当前页面编辑，但需导出备份以免刷新丢失。

演奏时仍只使用摄像头，鼠标 / 触屏用于演奏前配置。握拳始终消音。切换映射会释放旧和弦并重置识别防抖；重新摆出手势即可演奏。

音符来自标准吉他调弦 E2–A2–D3–G3–B3–E4。常用开放和弦保留原指法，其余和弦搜索六根弦上 0–15 品的配音，保证包含全部所需音级且不混入其他音级，按根音低音、弦数与品位跨度择优。小图显示所用配音（高把位标注起始品），不是经过吉他教师审核的推荐指法。九度音可在吉他配音中压缩到较低八度。

## 算法与延迟

- MediaPipe Hand Landmarker 输出两只手各 21 个关键点，在独立 Web Worker 中运行，优先 GPU，初始化失败时退回 CPU。兼容其 WASM 加载器，使用 classic worker 加动态 ESM 导入。
- 手势分类优先使用模型输出的真实三维关键点（world landmarks），计算手指关节角度和相对手掌距离，不额外训练分类模型；不要求手心朝镜头，也不依赖手指是否在画面中“朝上”。图像坐标用于骨架显示、手部大小检查和扫弦位置，三维坐标与所选手严格按同一索引配对。缺少三维数据时兼容图像关键点；严重遮挡、完全侧手或手指重叠仍可能让模型丢失或误判关键点。
- 和弦切换需要 110 ms 稳定手势。扫弦使用掌心纵向坐标的轻量平滑、跨线检测、速度门槛、4% 高度回差与 115 ms 冷却，避免轻微抖动连续发声。追踪间断超过 180 ms 时重置运动历史。
- 最多一个视频帧在途，目标采样上限约 30 FPS；识别耗时超过 300 ms 的旧帧不会发声。第一帧允许最多 15 秒完成 GPU 冷启动预热，之后识别线程超过 5 秒无响应则释放摄像头并提示重试。
- Web Audio 使用 Karplus–Strong 拨弦合成、分数延迟音准补偿和逐弦错峰。没有外部音频下载。

界面 FPS 是实际收到的识别结果帧率；“ms 识别”从截取视频帧前计时到主线程收到结果，包含位图转换、线程通信与模型推理，**不包含摄像头曝光、手势稳定等待和扬声器延迟**。

在开发机 Edge 无头浏览器、模拟摄像头下，实际模型链路的单次检查约为 29 FPS、21 ms 往返。这只证明模型加载与视频推理能运行，不代表真人手势准确率或手机性能。真实摄像头、双手遮挡、手机浏览器与主观音色仍需设备实测。

## 验证

```sh
npm test
npm run build
```

单元测试覆盖 0–12 手势、手心与手背视角、三维旋转、透视与画幅比例变化、尺度变化、非法数据、防抖、追踪丢失、上下扫、慢速动作、抖动、灵敏度和双手分配。

浏览器检查需要先启动 dev 或 preview 服务，以及安装 Playwright 的浏览器：

```sh
npx playwright install chromium
npm run test:browser
```

Windows 已安装 Edge 时可在 PowerShell 中使用：

```powershell
$env:BROWSER_CHANNEL = 'msedge'
npm run test:browser
```

`APP_URL` 可覆盖测试站点地址。检查会先使用模拟摄像头运行**真实模型与 Worker**，检查帧率与三维数据传递；再在测试环境的 Worker 消息边界注入合成的手背视角关键点，检查三维坐标与双手索引配对、选和弦、扫弦及握拳消音。还覆盖停止与重开、权限拒绝提示、390px 页面宽度，以及真实 Web Audio 合成的信号和 A3 音准。新增检查还覆盖 12 个演奏手势、自定义和弦实际发声、歌曲复制 / 切换、取消编辑、刷新持久化、导入导出、删除与存储故障提示。截图与结果写入忽略提交的 `test-results/`。合成关键点不是录制的真人手势，它没有验证真人手背姿势的识别率。

## 构建与手机路线

```sh
npm run setup
npm run build
npm run preview
```

将 `dist/` 的完整内容放到 HTTPS 静态站点的根目录，包括 `models/`、`mediapipe/` 与 `vision.worker.js`。当前资源路径以 `/` 开头，若部署到 `/musician/` 等子路径，需要同时调整应用和 Worker 的资源基址。`npm run build` 前必须完成 setup。

页面已有窄屏布局、前置摄像头偏好和 `playsinline`。手机访问局域网 `http://电脑IP:5173` 通常无法使用摄像头，因为它不是安全上下文；手机试用需要 HTTPS。此版本没有打包原生 App，也尚未完成 iOS / Android 真机验证。

后续可以先部署 HTTPS 网页，在实际手机上测量 FPS、识别延迟和功耗，再决定是否封装为 Capacitor App。手势与扫弦状态机在 `src/gestures.js`，不依赖 DOM；音频在 `src/audio.js`；识别模型调用在 `public/vision.worker.js`。原生迁移可以保留同样的关键点协议及状态机，把摄像头和模型推理替换为原生 MediaPipe Tasks，把声音替换为低延迟音频引擎。并发模型只处理一个在途帧，便于控制手机发热与内存占用。
